A redirect loop usually means the middleware runs before the session cookie is written. I should read the auth middleware and the login route, then check the order of cookie-set vs redirect.

Found it. In login.ts the session cookie is set after res.redirect() returns, so the browser leaves before the Set-Cookie header is written. The next request arrives unauthenticated and the middleware sends it back to /login — hence the loop.

The fix is to write the cookie first, then redirect.

›editsrc/routes/login.ts
const token = signJwt(user); + res.cookie('sid', token, { httpOnly: true, sameSite: 'lax' }); return res.redirect(next ?? '/'); - res.cookie('sid', token, { httpOnly: true });
