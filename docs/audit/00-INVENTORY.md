# Merged bug & risk inventory

Merged from the eight per-area audits at HEAD d17dbd2 — core loop, storage, tools/sandbox, shell, background service, resource policy, chat UI and projects — deduplicated by root cause. Original severities are preserved; where several reports describe the same defect the rows are collapsed into one entry and the other report is named inline ("also in …"). Raw counts before merging were P0 4, P1 27, P2 56, P3 28; the P3 tail is not carried over.

## P0 — crashes and data loss

| # | Area | Finding | Where | Fix sketch |
|---|---|---|---|---|
| 1 | Storage | `quarantine()` runs on *any* null handle from `openOrCreateDatabase`, so a transient I/O failure renames a healthy DB to `.corrupt-<ts>` and starts an empty one | 02-storage 77–93 | Quarantine only when `integrityOk` actually returned false; rethrow a distinguishable "storage unavailable" otherwise |
| 2 | Storage | A throwing migration is never caught: `db()` leaves `opened` unassigned and unclosed, so every later `db()` re-runs open→migrate→throw — permanent launch crash-loop with a leaked handle | 02-storage 42–47, 124–135; also in 02-storage #5, #6 | Wrap open+integrity+migrate+checkpoint in try/catch, close the candidate handle, leave `database` null |
| 3 | Background | `stop(context)` only calls `stopService`; the stop handler runs exclusively in the `ACTION_STOP` branch, so "stop" stops the service and not the run — the run continues with no FGS, no wake lock, no notification | 05-background 279–281 vs 59 | Route every termination path through one idempotent `teardown()` that invokes `RunControl.stopHandler` |
| 4 | Resource policy | `release(semaphore)` accepts any `Semaphore` with no permit accounting, so a double or unmatched release inflates permits above the cap and nothing detects or corrects it | 06-resource-policy 87–89; also in 04-shell | Replace raw acquire/release with a single-use lease token that can be released exactly once |

## Cross-cutting themes

- **Slots and leases are released on the happy path only.** `execute` vs `openPty` in 04-shell, `lease()`/`db()` in 02-storage, `release()` in 06-resource-policy, and the four termination paths in 05-background all release the resource on the success branch and leak it on the failure branch.
- **`runCatching` hides user-visible failures.** 05-background (start, stop handler, update, notifyComplete, ensureChannel), 02-storage (checkpoint, integrity override), 01-core (store reads/writes), 06-resource-policy (`release`, `availableSlots`), 08-projects (create, migration) — every one converts a real error into silence.
- **Check-then-act / TOCTOU.** Containment check vs open in 03-tools, `closed` re-check after `refs++` in 02-storage, unsynchronised `@Volatile` wake-lock check in 05-background, gate sizing in 06-resource-policy, and prefs-before-delete in 08-projects.
- **The reported state is not the real state.** "`[timeout] … was cancelled`" while the process still writes (01-core), "stop" that stops only the service (05-background), "installed" set before install (04-shell), a truncated partial promoted to a finished answer (01-core), `totalLines` that is really a scan cap (03-tools), "failed to launch" for a launched command (04-shell).
- **State computed but never consumed.** `pauseReason()`, `DEFAULT_NICE` and `clampConcurrency()` in 06-resource-policy are computed and exported but never read by the gate or `acquire()`; similarly `evaluateOverflow` disables trim/compact on any open call and never recovers.
- **No watchdog on unbounded growth.** `sharedRunLocks` never evicted (01-core), PTY `Channel.UNLIMITED` (04-shell), `while(true)` with `maxSteps == null` (01-core), WAL growth after a swallowed checkpoint (02-storage), unbounded retry backoff (01-core).
- **Blocking waits on shared threads with no deadline.** The ASK/question gate (01-core), `ResourcePolicy.acquire` up to 60 s (06-resource-policy), the instance monitor across open+migrate (02-storage), and `killProcessTree` blocking 5–6 s on the IO dispatcher (04-shell).
- **Duplicated derivations that recompute per event.** Two tail-pin effects and `steps`-keyed `remember`s in 07-perf-ui; two sources of truth for concurrency in 06-resource-policy; two copies of the 48-char name cap in 08-projects; redundant `remember(forceOpenIndex, steps, display)`.

## Recommended fix order

1. **Collapse `RunService` termination into one idempotent `teardown()`** (05-background, `RunService.kt`): invoke `RunControl.stopHandler`, `stopForeground(STOP_FOREGROUND_REMOVE)`, release and null the wake lock, clear `alive`/title/session, plus a `stoppedExplicitly` flag. Cheapest fix in the set (one file, one seam) and it closes the P0 where a run survives its own service, plus P1 #13/#14.
2. **Make `db()` failure-safe and quarantine-only-on-corruption** (02-storage, `AndroidDatabase.kt`): try/catch around open+integrity+migrate+checkpoint, close the candidate handle on failure, escalate to `quarantine()` only when `integrityOk` was false. Second P0, small diff, and it stops a recoverable I/O blip from looking like total data loss.
3. **Replace `ResourcePolicy.acquire/release` with a single-use slot lease** (06-resource-policy): owner token, one release, watchdog rebuild, `pauseReason()` consulted at acquire. Third P0 and the prerequisite for the shell fixes in step 4 — the current API cannot tell a leak from a live holder.
4. **Fix the shell slot/process ownership** (04-shell): move `killProcessTree` into the same `finally` as the release, close the PTY session in a `finally` + `invokeOnCompletion`, and scrub env on the Debian path. Depends on step 3's lease type, so it comes immediately after; closes P1 #11/#12.
5. **Supervise the tool boundary in `AgentLoop`** (01-core): child Job the loop owns, process registry on `ToolContext`, destroy + bounded grace on timeout/cancel, refuse DONE/ERROR while alive; default `maxSteps` to a finite value. Largest single risk reduction (P1 #1/#2) but a real refactor — placed after the cheap ownership fixes that give it a lease/registry to build on.
6. **Fix the core retry/streaming truthfulness** (01-core): emit `PartReset` and fresh part ids on overflow retry, drop the ERROR partial from retry context, mark continuation messages synthetic, make the doom-loop guard consecutive-only and return its error as a tool result. Same file as step 5, but independent and much smaller — do it here while the file is fresh.
7. **Close the storage lease and migration-probe gaps** (02-storage): `lease()` returns the pinned handle, retire bare `db()`, probe for `snapshots`/`messages.seq` before use, index the v2 temp table. Follows the P0 fix in step 2 in the same file and removes the "bricked install" paths.
8. **Make external-directory access atomic** (03-tools): open once and verify the descriptor's real path, canonicalise roots in the constructor, reject `/` and `$HOME`, add a type floor. Highest-severity sandbox finding, but needs a new open-verify-enumerate structure — after the cheaper integrity work.
9. **Stabilise the chat recomposition hot path** (07-perf-ui): `remember(value)` the pulse lambda, hoist each row's modifier chain, merge the two tail-pin effects, drop `steps` from the `forceOpenId`/backlinks keys. Pure-jank fixes with no behavioural risk and a large per-token win — cheap enough to slot in early, but nothing else depends on it.
10. **Make project prefs transactional with the filesystem** (08-projects): add `rename(id, name)`, set active after a successful create, remove name/active keys only after `deleteTree` succeeds and roll back otherwise, validate `activeOrNull()` with `isSafeId`. Fixes a P1 data/UX cluster in one file once the higher-risk storage work is done.
11. **Harden background notification plumbing** (05-background): single id/request-code registry, permission and channel checks with a plain-notification fallback, logged rather than swallowed update/complete failures. Follows step 1 in the same file; lower risk but needs the teardown seam in place first.
12. **Policy and storage-refactor tail** (06-resource-policy, 02-storage): route the nice decision through `ResourcePolicy` so the constant has one owner (it is already applied in `AndroidShellExecutor.startUnderSetsid`), switch thermal gating to `PowerManager` status with hysteresis, and move open+migrate out of the instance monitor with the missing `todos`/`snapshots` indexes. Deliberately last: these are advisory-quality improvements and schema/index changes that want the rest of the storage work settled first.
